# 第 0 层：这个项目到底是什么

## 0.1 「脚本」和「服务」的区别

你以前写的 Python 大概是这样：运行 → 算出结果 → 程序结束。

这叫**脚本**。特点是：**跑完就没了**。

我们要做的东西叫**服务（Service）**：启动之后**一直待在那里**，等别人来找它。
别人发一条消息过来，它处理完把结果发回去，然后继续等下一个。

**为什么要"一直等"？** 因为用你程序的人不在你电脑旁边。
你室友的手机、面试官的浏览器、你以后写的网页，都是**通过网络**来找你的程序。
程序如果跑完就退出，别人就永远找不到它。

**类比：餐厅**

| 餐厅 | 我们的项目 |
|---|---|
| 一直开门营业 | 服务一直运行 |
| 菜单上的菜名和价格 | API 文档（`/docs`） |
| 你点单"一份宫保鸡丁" | 发一个 HTTP 请求 |
| 厨房做菜 | 服务处理业务逻辑 |
| 端上来一盘菜 | 返回 HTTP 响应 |
| "这道菜卖完了" | 404 |

## 0.2 三层角色的分工

一个 Web 服务最少涉及三个角色：

```
浏览器 / 手机App / Postman      ← 客户端：发起请求的人
        ↓ HTTP 请求
    你的服务（后端）             ← 后端：处理逻辑、算结果
        ↓ SQL
      数据库                    ← 数据库：把数据存下来
```

- **前端**：用户看得见的界面。负责"好看、好点"，不负责算。
- **后端**：用户看不见。负责"算得对、存得住、别崩"。
- **数据库**：负责"关机也不丢"。

我们这次做的**只有后端**。前端是以后的事。

## 0.3 为什么后端要单独存在

能不能把逻辑写在网页里？不能，有三个硬原因：

1. **密钥不能给用户**。调大模型要 API Key。写在网页里，任何人按 F12 就能看到，然后拿去刷你的钱。
2. **数据要所有人共享**。你存的数据必须让所有用户看到同一份，不能存在各自手机里。
3. **规则不能被绕过**。比如"一集短剧最多 20 个镜头"，写在网页里，用户改改代码就绕过去了。写在后端，他改不了。

**记住一句话**：**凡是"不能相信用户"的东西，都必须放在后端。**

# 第 1 层：HTTP —— 最底层的一次对话

## 1.1 一次请求长什么样

HTTP 请求本质上就是一段格式固定的文本：

```
POST /api/v1/dramas HTTP/1.1          ← ① 方法 + 路径 + 协议版本
Host: 127.0.0.1:8000                  ← ② 头（Headers）：附带的元信息
Content-Type: application/json

{"title": "雨夜便利店"}                ← ③ 体（Body）：真正要传的数据
```

三部分：**方法**（想干什么）、**路径**（对谁干）、**体**（带什么数据）。

## 1.2 四个最常用的方法

| 方法 | 含义 | 我们项目里的例子 |
|---|---|---|
| GET | 读取 | `GET /api/v1/dramas/1` 查看第 1 部短剧 |
| POST | 创建 | `POST /api/v1/dramas` 新建一部短剧 |
| PATCH | 局部修改 | `PATCH /api/v1/dramas/1` 只改标题 |
| DELETE | 删除 | `DELETE /api/v1/dramas/1` 删掉它 |

**为什么不是一个"操作"方法就够了？** 因为方法本身携带语义。
`GET` 被规定为"只读、不改变任何东西"，所以浏览器、缓存、爬虫都敢放心重复发。
这个性质叫 **幂等（idempotent）** —— 同一个请求发一次和发五次，结果一样。

> 第 7 层你会看到"重新生成分镜"也是幂等的，那是同一个思想。

## 1.3 响应：状态码 + 数据

```
HTTP/1.1 201 Created                  ← 状态码
Content-Type: application/json

{"id": 1, "title": "雨夜便利店", ...}   ← 数据（JSON）
```

状态码是三位数字，**第一位表示大类**：

| 码 | 含义 | 我们项目里的用法 |
|---|---|---|
| 2xx | 成功 | 200 正常、201 创建成功、204 删除成功（无内容） |
| 4xx | **调用方**错了 | 404 找不到、409 冲突、422 参数不合法 |
| 5xx | **服务端**错了 | 500 内部崩了、502 上游（大模型）出问题 |

**4xx 和 5xx 的区别极其重要**：4xx 是你的问题，5xx 是我的问题。
线上出故障，先看是 4 还是 5，就知道该找前端还是找后端。

## 1.4 JSON 是什么

一种文本格式，用来表示结构化数据，长得像 Python 的字典和列表：

```json
{
  "title": "雨夜便利店",
  "shots": [
    {"number": 1, "shot_type": "特写"},
    {"number": 2, "shot_type": "全景"}
  ]
}
```

**为什么不用 Python 的字典格式？** 因为要**跨语言**。
换成 Java、JavaScript、Go 写的客户端也得能读。跨语言通信需要一个中立格式，JSON 是现在的事实标准。

## 1.5 URL 里的 `/api/v1` 是什么

```
http://127.0.0.1:8000  /api/v1  /dramas  /1
└──── 地址和端口 ────┘  └─版本─┘  └资源─┘ └ID┘
```

- `127.0.0.1` = 本机（localhost）
- `8000` = 端口。一台机器上可以跑很多服务，端口用来区分。就像一栋楼里不同的房间号。
- `/api/v1` = **版本号**。接口一旦给出去，就不能随便改字段名（用户的手机会崩）。
  留一个 v1 位，将来不兼容的改动可以并行发 v2，老客户端不会立刻崩。

# 第 2 层：环境 —— 虚拟环境到底是干什么的

## 2.1 先说 pip 和"包"

Python 自己只带标准库（`os`、`json`、`datetime` 这些）。
我们项目用到的 FastAPI、SQLAlchemy 都是**别人写的第三方库**，需要先下载安装。

**pip** 就是 Python 的包管理器（相当于手机的应用商店）：

```bash
pip install fastapi        # 下载并安装 fastapi 包
```

## 2.2 问题来了：包是装在"全局"的

如果你直接 `pip install fastapi`，它会装到 Python 的全局目录里，
**这台机器上所有项目共用这一份**。

于是冲突就来了：

```
项目 A 需要 fastapi 0.100  → 依赖的 starlette 是 0.27
项目 B 需要 fastapi 0.143  → 依赖的 starlette 是 1.7
```

同一次只能存在一个版本。你装 B 的时候，A 就跑不起来了。
更糟的是：哪天你误删一个包，别的项目也一起坏掉。

**这类问题叫"依赖地狱"，是所有语言的通病。**

## 2.3 解决方案：虚拟环境

**虚拟环境（virtual environment）就是一个文件夹**，里面装着一套**独立的** Python 包。

```
ai-drama-studio\.venv\            ← 这就是我们的虚拟环境
├── Scripts\python.exe            ← 用这个 python 启动，它只认这个环境里的包
├── Lib\site-packages\            ← 本项目专属的包都在这
│   ├── fastapi\
│   ├── sqlalchemy\
│   └── ...
└── pyvenv.cfg                    ← 记录"我是从哪个 Python 建的、版本是多少"
```

创建它只要一行：

```bash
python -m venv .venv          # 意思是：用 venv 模块，在当前目录建一个叫 .venv 的环境
```

**"激活"（activate）是什么？**
激活本质上就是**改了一下 PATH 环境变量**，让命令行里的 `python` 指向这个环境里的 python.exe。
激活后命令行前面会出现 `(.venv)`：

```bash
(.venv) PS C:\...\backend> python -V
Python 3.12.3
```

**为什么 `.venv` 不能提交到 Git？**
因为它有 70MB+，而且**换一台机器就必须重建**（Windows 的包在 Mac 上不能用）。
正确做法是提交一份"清单"，别人照着重装 —— 那份清单叫 `requirements.txt`。

## 2.4 requirements.txt：依赖清单

```
fastapi==0.143.0
uvicorn==0.54.0
SQLAlchemy==2.1.4
```

**为什么要写死版本号（`==`）而不是只写 `fastapi`？**

因为"**昨天还能跑，今天重装就挂了**"最常见的原因就是：上游发了个新版本。
写死版本 = 你的项目在任何时间、任何机器上装出来的东西都一样。
这叫**可复现（reproducible）**，是工程化的基本要求。

要升级的时候**显式改这个文件**并重跑测试 —— 而不是被动地被上游推着走。

> **顺带解释你踩过的两个坑**（见 `docs/02`）：
> 1. 这个文件里曾经写中文注释，pip 在中文 Windows 上按 GBK 读 UTF-8 文件，直接崩。
>    所以现在文件开头写着 `keep this file pure ASCII`。
> 2. `--only-binary=:all:` 这行是强制"只用预编译好的包"，不许 pip 现场编译 C 代码。

# 第 3 层：Web 框架 —— FastAPI 帮我们做了什么

## 3.1 不用框架会是什么样

HTTP 请求进来的本质是一堆**字节**。你要自己：

1. 解析这堆字节，找出方法、路径、头、体
2. 判断路径是什么，分发到对应函数
3. 手动解析 JSON
4. 手动验证每个字段（是不是空、长度对不对、类型对不对）
5. 手动把结果转成 JSON
6. 手动设置状态码和响应头
7. 手动写文档告诉前端有哪些接口

这七件事**每个项目都一样**，没有业务价值。所以有人把它们打包成了**框架**。

## 3.2 FastAPI 替我们做了这四件事

**① 路由：把"路径"和"函数"对应起来**

```python
router = APIRouter(prefix="/dramas", tags=["dramas"])

@router.post("", response_model=DramaRead, status_code=201)
def create_drama(payload: DramaCreate, db: DbSession) -> Drama:
    ...
```

那行 `@router.post(...)` 叫**装饰器**。它的作用是：
"当有人用 POST 方法请求 `/api/v1/dramas` 时，就调用下面这个函数"。

没有它，你得写一大串 `if path == "/dramas" and method == "POST": ...`。

**② 参数校验：自动检查数据对不对**

`payload: DramaCreate` 这个类型标注，FastAPI 会拿它去**校验请求体**。
`title` 是空的？自动返回 422，**你的业务代码根本不会被执行**。

**③ 自动生成接口文档**

因为有了类型标注，FastAPI 能自动生成一份可交互的文档，在 `/docs`。
**你不用写文档，也不用维护文档** —— 这一点在团队协作里价值极大。

**④ 异步支持**

见下一节，这是选 FastAPI 最重要的理由。

## 3.3 为什么必须是"异步"的（面试高频）

先看两种等待方式：

**同步（阻塞）**：你打电话问餐厅"我的菜好了吗"，然后**一直拿着话筒不挂**，
服务员没法接别人的电话。等 30 秒，就浪费 30 秒。

**异步（非阻塞）**：你问完就挂断，说"好了打给我"。
这 30 秒里服务员能接 100 个别的电话。

我们的场景：**调用大模型生成剧本要等几十秒**。
如果同步处理，一个用户生成剧本，服务器就卡住几十秒不能服务别人 —— 10 个人同时点，就排 10 分钟。

```python
@router.post("/{episode_id}/generate")
async def generate_script(...):          # ← async 关键字
    return await generate_episode_script(...)   # ← await：这里让出控制权，去干别的
```

**`async def` + `await` 的含义**：执行到 `await` 时，如果这件事在等网络，
**把 CPU 让出来**去处理别的请求，等结果回来再接着往下走。

## 3.4 uvicorn 又是什么

FastAPI 是"框架"（规定怎么写代码），uvicorn 是"服务器"（真正监听端口、收发字节）。

```
uvicorn（服务器） → 收到 HTTP 请求 → 交给 FastAPI（框架）→ 交给你的函数
```

这就是为什么启动命令是 `uvicorn app.main:app` ——
意思是"用 uvicorn 启动，加载 `app.main` 模块里的 `app` 这个对象"。

# 第 4 层：Pydantic —— 数据校验与"契约"

## 4.1 没有校验会怎样

假设前端发来这个东西：

```json
{"title": "", "genre": 12345}
```

不校验的话，你会把空标题和数字题材存进数据库。
三天后产品经理说"为什么列表里有条空名字的剧？"，你得写脚本去清理。

**校验必须发生在数据进门的那一刻**，越早挡住越省事。

手写校验是这样：

```python
if not data.get("title") or len(data["title"]) > 120:
    return {"error": "标题不合法"}
if not isinstance(data.get("genre"), str):
    ...
```

十个字段就要写二十行，而且很容易漏。

## 4.2 Pydantic 的做法：用类描述数据形状

```python
class DramaCreate(BaseModel):
    title: str = Field(min_length=1, max_length=120)
    genre: str = Field(default="都市", max_length=40)
```

这一小段就表达了：`title` 必须有、是字符串、长度 1~120；`genre` 可选、默认"都市"。

**数据不合法时，FastAPI 自动返回 422，并告诉前端哪个字段错了。** 你一行都不用写。

## 4.3 Schema 和数据库模型为什么要分成两套（重点）

项目里有两组"长得差不多"的类：

| | 位置 | 作用 |
|---|---|---|
| **ORM Model** | `app/db/models.py` | 描述**数据库里的表**长什么样 |
| **Schema** | `app/schemas/*.py` | 描述**接口收发**的数据长什么样 |

看上去是重复劳动。为什么不合并成一个？

**理由一：安全（这条最要命）**

假设你直接用数据库模型当接口返回。今天表里有 `title`、`genre`。
明天你加了个字段 `owner_phone`（用户手机号）——

**它会自动出现在所有接口的返回里，你什么都没做，就泄露了用户隐私。**

分开写的话，`DramaRead` 里没有这个字段，接口就不会返回它。

**理由二：两者本来就不一样**

- 数据库有 `created_at`，但创建接口不需要传它
- 创建请求必须有 `title`，但改标题的请求 `title` 可以不带
- 前端列表页可能想要"剧名 + 集数"，而数据库里根本没"集数"这个列

所以 `schemas/` 里每个概念有三个类：

```python
DramaCreate   # 创建时要传什么（title 必填）
DramaUpdate   # 修改时要传什么（全部可选）
DramaRead     # 返回时给什么（带 id 和时间戳）
```

**这叫"契约（contract）"**：我承诺接口长这样，你按这个来调，别的细节我不保证。
契约稳定，前端才敢放心开发。

# 第 5 层：数据 —— 存到哪里、怎么存

## 5.1 为什么不放在变量里

```python
dramas = []      # 存在内存里
```

三个致命问题：

1. **一重启就没了**。服务重启、电脑断电，数据全丢。
2. **多个实例看不到彼此**。以后为了扛住流量，会同时跑好几个服务进程，
   它们各有各的 `dramas` 列表，用户 A 存的数据用户 B 看不到。
3. **没法查询**。"找出所有都市题材、按创建时间倒序、只看前 20 条" ——
   用列表你就得写循环，数据一多就慢死。

所以需要**数据库**：一个专门的程序，负责把数据可靠地存到磁盘上，并且能高效查询。

## 5.2 SQL 和"表"的基本概念

数据库用**表（table）**组织数据，非常像 Excel：

| id | title | genre | status |
|---|---|---|---|
| 1 | 雨夜便利店 | 都市 | ready |
| 2 | 重生之我在北京写代码 | 都市 | draft |

- **行（row）**：一条记录，例如 1 号短剧
- **列（column）**：一个字段，例如 `title`
- **主键（primary key）**：`id`。唯一标识一行。身份证号
- **外键（foreign key）**：指向另一张表的 id，用来建立关联

操作数据库的语言叫 **SQL**：

```sql
SELECT * FROM dramas WHERE genre = '都市' ORDER BY id DESC LIMIT 20;
```

## 5.3 ORM 是什么，为什么要用它

如果直接用 SQL，你的 Python 代码里到处是字符串：

```python
cursor.execute("SELECT * FROM dramas WHERE id = %s", (drama_id,))
row = cursor.fetchone()
title = row[1]        # 1 是第几列？得去数
```

问题：**列的位置变了、表名改了、字段打错字，都是运行时才炸**，而且没有自动补全。

**ORM（Object-Relational Mapping，对象关系映射）**把"表"映射成"类"：

```python
class Drama(Base):
    __tablename__ = "dramas"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(120))
```

于是查询变成这样：

```python
drama = db.get(Drama, drama_id)        # 比我手写 SQL 清楚得多
drama.title = "新标题"
db.commit()
```

好处：
1. **有类型提示**：写错字段名编辑器立刻报红，不用等运行
2. **不用记列顺序**
3. **能防 SQL 注入**（自动做参数转义，这是安全问题）
4. **换数据库方便**：写的是 Python，不是某家数据库的方言

## 5.4 Engine 和 Session 是什么（面试常问）

- **Engine（引擎）**：连接池 + 数据库驱动。整个进程一个就够，**线程安全**。
  你可以理解成"一个电话总机"。

- **Session（会话）**：一次工作单元。**不是线程安全的**，所以**每个请求一个**。
  可以理解成"一通电话"。打电话的时候谈事情（增删改查），谈完挂掉。

- **`get_db` 这个函数为什么用 `yield`？**

```python
def get_db() -> Iterator[Session]:
    with get_session_factory()() as session:
        yield session
```

`with` 保证：**不管请求成功还是抛异常，Session 最后都会被关闭**。

如果写成"返回一个 Session 但不管关闭"，跑一段时间连接池就被占满，
服务直接卡死 —— 这是新手最常见的线上事故之一。

## 5.5 我们项目的表设计

```
Drama（短剧）         id, title, genre, logline, style, status
   │  1 : N
Episode（剧集）       id, drama_id, number, title, synopsis, status
   │  1 : N
Shot（镜头/分镜）     id, episode_id, number, shot_type, camera,
                      description, dialogue, duration_sec, image_prompt
```

**为什么拆成三层而不是塞一张表？**

1. 一部剧有多集，一集有多个镜头 —— 硬塞一张表就得重复存剧名、剧名重复就容易改漏
2. 删一部剧时，剧集和镜头应该跟着消失 —— 这叫**级联删除（cascade）**
3. 生成剧本时只动 Shot 表，不用碰别的
4. **这也是短剧行业真实的业务结构** —— 面试时能讲清"为什么这样建模"，
   比"我会用 ORM"值钱得多

## 5.6 两个必须知道的坑

**坑一：`create_all` 不能用于生产**

```python
Base.metadata.create_all(engine)   # 表不存在就建，已存在就跳过
```

它**只会新建，不会修改**。你给 Shot 加了字段，它不会帮你加列，
线上就会报 `Unknown column`。

生产环境必须用 **Alembic**（数据库迁移工具）：每次结构变更生成一个脚本，
可以 review、可以回滚、可以按顺序执行。**这是本项目的待办项。**

**坑二：SQLite 和 MySQL 的差异**

- 开发用 SQLite（单文件、零配置，clone 下来就能跑）
- 生产用 MySQL（真并发、多实例、备份权限体系）
- 切换只要改 `DATABASE_URL` 一个环境变量 —— 但要注意：
  - SQLite 的外键约束**默认是关的**，`ondelete="CASCADE"` 可能不生效
  - MySQL 的 `utf8` 是残缺实现，连接串必须写 `charset=utf8mb4`，否则中文 emoji 存不进去

# 第 6 层：分层架构 —— 代码为什么要分文件夹

## 6.1 全塞在路由函数里会怎样

```python
@router.post("/episodes/{id}/generate")
def generate(id):
    # 检查剧集存在
    # 拼提示词
    # 调大模型
    # 解析返回
    # 清洗数据
    # 写数据库
    # 记录日志
    # ...80 行
```

第一个月能跑。第三个月：**没人敢改**，加需求就是加 `if`。

## 6.2 我们的分层

```
app/
├── api/        接口层   —— 只负责"怎么暴露"（收参数、返回结果），10 行以内
├── services/   业务层   —— "业务怎么做"（提示词、清洗、落库）
├── db/         数据层   —— "数据怎么存"（表结构、连接）
├── schemas/    契约层   —— "接口收发什么数据"
└── core/       基础设施 —— 配置、日志、错误处理
```

**依赖方向是单向的**：`api → services → db`。
接口层可以调业务层，业务层**不应该**反过来调接口层。

## 6.3 这样分有什么实际好处

**好处一：业务逻辑能被复用。**
`generate_episode_script()` 这个函数，可以给 HTTP 接口用，
也可以给定时任务用（"每晚 2 点批量生成明天要发的剧"），也可以给命令行脚本用。
如果逻辑写在路由函数里，就只能被 HTTP 调用。

**好处二：能单独测试。**
测试可以直接调 `_extract_json()` 这个函数，不需要启动整个服务、发 HTTP 请求。

**好处三：换东西只改一层。**
换 Web 框架 → 只改 `api/`；换数据库 → 只改 `db/`；换大模型 → 只改 `services/llm/`。

## 6.4 依赖注入（Dependency Injection）是什么

看这一行：

```python
def create_drama(payload: DramaCreate, db: DbSession) -> Drama:
```

函数**没有自己去创建数据库连接**，而是声明"我需要一个 db"，然后**有人递给它**。

那个 `DbSession` 是这么定义的：

```python
DbSession = Annotated[Session, Depends(get_db)]
```

`Depends(get_db)` 的意思是："每次调用这个函数之前，先执行 `get_db`，
把结果作为参数传进来"。这个机制叫**依赖注入**。

**为什么这么做？好处是"可替换"。**

测试的时候我们这样写：

```python
app.dependency_overrides[get_db] = override_get_db   # 换成测试用的数据库
```

一行就把**所有接口**用的数据库换成了临时的测试库。
如果每个函数都自己写 `SessionLocal()`，你就得改二十个地方。

**这就是"依赖注入"最大的价值：不是为了少写代码，而是为了能替换。**

# 第 7 层：接大模型 —— Provider 抽象（本项目的核心设计）

## 7.1 最直接的做法和它的问题

```python
from openai import OpenAI
client = OpenAI(api_key="sk-xxx")
resp = client.chat.completions.create(...)
```

能跑。问题是：

1. **测试没法跑**。每次跑测试都真的去调大模型 → 要联网、要花钱、
   而且模型有随机性，**测试会随机失败**。会随机失败的测试等于没有测试。
2. **换模型要改代码**。DeepSeek 换通义，SDK 不一样，你得改遍所有调用点。
3. **模型挂了服务就挂了**，没有降级空间。

## 7.2 我们的做法：把"调模型"抽象成一个接口

```python
# services/llm/base.py
class LLMProvider(ABC):
    @abstractmethod
    async def complete(self, *, system: str, user: str) -> str:
        ...
```

然后写两个实现：

| 实现 | 文件 | 用途 |
|---|---|---|
| `MockProvider` | `mock.py` | 返回写死的假数据。**不联网、不花钱、结果稳定** |
| `OpenAICompatProvider` | `openai_compat.py` | 真的调大模型 |

业务代码**只认接口**，不认具体实现：

```python
async def generate_episode_script(..., provider: LLMProvider, ...):
    raw = await provider.complete(system=SYSTEM_PROMPT, user=user_prompt)
```

最后用**工厂**根据配置选一个：

```python
# services/llm/factory.py
def build_provider(settings):
    if settings.llm_provider == "mock":          return MockProvider()
    if settings.llm_provider == "openai_compat": return OpenAICompatProvider(...)
```

**这个模式叫"依赖倒置原则（DIP）"** —— 高层模块不依赖低层实现，两者都依赖抽象。

## 7.3 Mock 的三重价值（别小看它）

1. **能测试**：CI 不联网、不花钱、不会因模型抽风而随机失败
2. **能离线开发**：API Key 还没申请下来，也能把整条链路调通
3. **能省钱**：开发阶段每次调试都真调模型，一天可能烧掉几百块

**"我给 LLM 调用做了抽象，测试用假实现，所以 CI 不依赖外部 API"** ——
这句话在面试里很值钱，因为它证明你理解**可测试性**，而不只是会调 API。

## 7.4 为什么用"OpenAI 兼容协议"

DeepSeek、通义、Kimi、智谱、OpenAI、本地 Ollama 都提供同一套接口：
`POST {base_url}/chat/completions`。

所以只写一份适配器，**改三行配置就能换模型**：

```
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_API_KEY=sk-xxx
```

## 7.5 AI 应用和传统后端的根本差异

传统后端：上游（数据库）**确定**。查不到就是查不到。

AI 应用：上游（大模型）**是概率性的**。哪怕你在提示词里写"只输出 JSON"，
它仍可能给你包一层 ```` ```json ````，或者开头加一句"好的，这是您要的剧本："。

所以必须有容错解析：

```python
def _extract_json(text: str) -> dict:
    fenced = re.search(r"```(?:json)?\s*(.*?)```", text, re.S)   # 先剥掉代码块
    raw = fenced.group(1) if fenced else text
    start, end = raw.find("{"), raw.rfind("}")                   # 再暴力找花括号
    ...
```

而且测试里专门有一条用例，验证"**模型返回垃圾文本时，返回 502 而不是 500 崩栈**"。

**"AI 应用开发的最大不同，是上游返回是概率性的，代码必须假设它不规范。"**
这句话面试说出来，面试官会知道你做过真东西。

## 7.6 幂等：为什么"重新生成"不会让镜头翻倍

```python
db.execute(delete(Shot).where(Shot.episode_id == episode.id))   # 先删旧的
# 再插入新的
```

如果只做插入，用户点两次"生成"就有 12 个镜头，点三次 18 个。
**"接口可以重复调用而不产生副作用"，这就是幂等。** 设计 API 时应该主动考虑。

# 第 8 层：测试 —— 为什么写、怎么写

## 8.1 不写测试会怎样

你改了一行代码，怎么知道有没有弄坏别的地方？

**手动点一遍**。点 20 个接口要 10 分钟。改 5 次代码就是 50 分钟。
于是你开始偷懒 → 不点了 → 上线 → 炸了。

**测试就是把这 10 分钟交给机器做。** 一条命令，1 秒钟。

## 8.2 我们的测试在测什么

```
tests/
├── conftest.py          ← 公共夹具：每个用例一个临时数据库
├── test_health.py       ← 健康检查 + OpenAPI 文档能生成
├── test_dramas.py       ← 增删改查、分页、参数校验、404、409
└── test_generation.py   ← AI 生成流程、幂等、坏模型返回 502
```

结果：**11 个用例，1 秒跑完。**

## 8.3 关键技巧：用"依赖覆盖"换掉数据库

```python
@pytest.fixture()
def client(tmp_path):
    engine = create_engine(f"sqlite+pysqlite:///{tmp_path / 'test.db'}")
    Base.metadata.create_all(engine)
    ...
    app.dependency_overrides[get_db] = override_get_db
    with TestClient(app) as c:
        yield c
```

三个要点：

1. `tmp_path` 是 pytest 给的**临时目录**。每个用例一个全新的空数据库，**互不污染**，
   跑完自动删。
2. `dependency_overrides` 把真实数据库换掉 —— 这就是第 6 层"依赖注入"的回报。
3. `Base.metadata.create_all` 建表 —— 模型改了，测试库自动跟着变。

**所以你本机不需要装 MySQL，测试也能跑。**

## 8.4 断言（assert）就是"我的预期"

```python
def test_generate_is_idempotent(client):
    _, episode = _prepare_episode(client)
    client.post(f"/api/v1/episodes/{episode['id']}/generate", json={"shot_count": 6})
    second = client.post(f"/api/v1/episodes/{episode['id']}/generate", json={"shot_count": 6})
    assert len(second.json()["shots"]) == 6      # ← 重复生成，还是 6 个
```

`assert` 后面写"我认为应该是什么"。不对就报错，并告诉你哪里不对。

**测试的另一个身份是"活的文档"**：半年后你忘了"重复生成会怎样"，
读这个用例的名字和断言，一秒就懂。

## 8.5 关于"会随机失败的测试"

这也是为什么测试必须用 MockProvider：

> 如果测试真的去调大模型，网络抖一下就红、模型抽风就红。
> **一个会随机失败的测试，团队三天内就会开始忽略它。** 那还不如不写。

# 第 9 层：部署 —— Docker、Nginx、CI 各自解决什么

## 9.1 Docker：解决"在我电脑上能跑"

**问题的根源**：你的电脑和我电脑上的 Python 版本、系统库、包版本可能都不一样。
"在我这能跑"这句话，本质是在说"环境差异"。

**Docker 的做法**：把"操作系统 + Python + 依赖 + 你的代码"全部打包成一个**镜像**。
测试环境、生产环境跑的都是同一个镜像，**差异被彻底消灭**。

```dockerfile
FROM python:3.12-slim              # 从官方 Python 3.12 镜像开始
WORKDIR /app
COPY requirements.txt .            # 先只拷依赖清单
RUN pip install -r requirements.txt   # 装依赖（这一步会被缓存，改代码不用重装）
COPY . .                           # 再拷代码
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**为什么先 COPY requirements.txt 再 COPY 代码？**
Docker 是一层一层构建并缓存的。只要依赖清单没变，这一层就命中缓存，
改代码后重建镜像只要几秒，而不是重装一遍依赖。

**为什么必须监听 `0.0.0.0` 而不是 `127.0.0.1`？**
`127.0.0.1` 意思是"只接受本机连接"。在容器里，容器外就是"别的机器"，
监听 127.0.0.1 的话外面永远访问不到。

## 9.2 Nginx：解决"公网入口该做的事"

Nginx 是一个高性能的 Web 服务器，放在你的服务前面当"门卫"：

```
公网用户 → Nginx（80/443） → 你的服务（8000，不暴露）
```

它做四件事：

1. **反向代理**：把请求转发给内部服务。应用端口不出公网，攻击面更小。
2. **TLS 终止**：HTTPS 证书只在 Nginx 配一次，后端只管明文 HTTP，代码更简单。
3. **超时控制**：**这一条对我们特别重要** —— 大模型生成要几十秒，
   Nginx 默认 60 秒就 504 了，必须显式调大。
4. **gzip 压缩、限流、静态文件**：这些通用能力不该写进 Python 代码。

## 9.3 CI：解决"提交就没人验证"

**CI（持续集成）**：每次 push 代码，机器自动跑一遍测试。

```yaml
# .github/workflows/ci.yml
- run: pip install -r requirements.txt
- run: pytest -q
```

**为什么对应届生特别重要？**
面试官打开你的 GitHub，看到有绿色 CI 徽章、有测试的项目，
和看到只有 main 分支一堆 "update" 提交的项目，印象完全不同。

更实际的价值：**它逼着你的代码必须是可测试的**。
如果你的代码依赖真实数据库、真实 API Key，CI 根本跑不起来。
"能上 CI"本身就是一种架构质量的证明。

# 第 10 层：工程习惯 —— 那些不起眼但很值钱的东西

## 10.1 Git：为什么不是"改完复制一份备份"

- 每次提交记录**改了什么、谁改的、为什么改**
- 能回到任何一个历史版本
- 多人改同一个文件能合并
- **GitHub 上的提交历史就是你的"工程履历"**

我们用到了 `.gitignore`（哪些文件不提交）和 `.gitattributes`（换行符统一）。

## 10.2 `.gitignore` 里为什么有 `.env`

```
.env
```

因为 `.env` 里要放 **API Key 和数据库密码**。
一旦提交，密钥就**永久留在 Git 历史里**（删掉文件也没用，得重写整个历史）。
这是新手最常见、代价最惨的安全事故之一。

正确做法：提交 `.env.example`（告诉同事需要配哪些变量），不提交 `.env`。

## 10.3 配置文件尽量保持 ASCII

这是我们在本项目真实踩到的坑：`requirements.txt` 里写中文注释，
在中文 Windows（GBK）上 pip 直接崩。

**教训**：配置文件是**跨环境**的东西，不要假设它一定按 UTF-8 被读取。

# 把整条链路串起来：一次请求的完整旅程

```
① 你在 /docs 页面点了"生成分镜"按钮
        ↓
② HTTP 请求：POST /api/v1/episodes/1/generate  {"shot_count": 6}
        ↓
③ Nginx 收到（生产环境），转发给内部服务 :8000
        ↓
④ uvicorn 收到字节，交给 FastAPI
        ↓
⑤ FastAPI 找路由 → 命中 episodes.py 里的 generate_script
        ↓
⑥ Pydantic 校验请求体（不合法 → 422，到此为止）
        ↓
⑦ 依赖注入：给函数递上 Session 和 LLMProvider
        ↓
⑧ 查数据库：第 1 集存在吗？（不存在 → NotFoundError → 404）
        ↓
⑨ 业务层 script_service：拼提示词
        ↓
⑩ await provider.complete(...)  ← 等几十秒。这期间服务器去处理别人的请求
        ↓
⑪ 拿到模型的文本 → _extract_json 容错解析（可能失败 → 502）
        ↓
⑫ 删除旧镜头 + 插入新镜头（幂等）→ commit 写进数据库
        ↓
⑬ Pydantic 按 EpisodeDetail 的形状序列化成 JSON
        ↓
⑭ 返回 200 + JSON，前端渲染出分镜表
```

**任何一步抛异常，都会被 `core/errors.py` 统一接住**，
返回同一种 JSON 结构：

```json
{"error": {"code": "not_found", "message": "剧集 1 不存在"}}
```

前端只需要写一套错误处理逻辑。

# 现在这个项目还缺什么（诚实清单）

| 缺失 | 风险 |
|---|---|
| **鉴权（JWT）** | 任何人都能调接口，上线前必须加 |
