# 部署验证清单（Docker / Nginx / MySQL）

> 这份清单的目标：**诚实地区分"已在本机验证"和"只能在有 Docker 的环境验证"**。
> 当前这台开发机**没有装 Docker**，所以 B 部分需要你装好 Docker Desktop 后按步骤执行。
>
> 配套脚本：`backend/_verify_docker_static.py` —— 不装 Docker 也能跑的 45 项静态检查
> （YAML 语法、COPY 路径、前端产物路径计算、忽略清单、nginx 结构、容器内 ffmpeg）。

## A. 已经在本机验证过的部分

### A1. 数据库与迁移（真实 MySQL 9.6 实测）

| 项 | 怎么验证的 | 结果 |
|---|---|---|
| 迁移能在干净库从零建表 | `alembic upgrade head`（空库） | ✅ 9 条迁移全部执行 |
| 迁移幂等 | 同一库再跑一次 `upgrade head` | ✅ 第二次无任何操作 |
| 模型与迁移零差异 | `alembic check` | ✅ "No new upgrade operations detected" |
| 真实 MySQL 全链路 | 本机 MySQL 9.6 + 冒烟测试 | ✅ 通过，utf8mb4 生效（emoji 往返正常） |
| `server_default('')` 语法 | SQLite/MySQL 上实际执行 `add_column` | ✅ 兼容 MySQL 8.0.13+ 的 TEXT 列 |
| 容器入口的迁移部分 | 直接跑 entrypoint 的核心命令 | ✅ `python -m alembic upgrade head` |

### A2. Docker / Nginx 配置的静态验证（45 项，全部通过）

`backend/_verify_docker_static.py` 检查了什么（**能查"配置对不对"，查不了"能不能跑起来"**）：

| 分组 | 检查内容 |
|---|---|
| compose 语法 | YAML 合法、三个服务齐全 |
| 构建上下文 | `context: ..`、Dockerfile 存在、**4 条 COPY 的源路径都存在** |
| **前端产物路径** | 复现并确认修复了"容器里界面 404"的路径计算 bug |
| `.dockerignore` | **密钥/虚拟环境/媒体会被排除**，代码/静态资源/依赖清单不会被误伤 |
| nginx 结构 | 花括号配平、**有 `location /`**、每个 location 都有 proxy_pass、媒体不缓冲、不 gzip 视频 |
| 容器内 ffmpeg | requirements 含 imageio-ffmpeg（自带含 libx264 的静态构建），无需 apt 装 |
| compose 关键配置 | **media 挂了卷**、四种模态 + 限额环境变量齐全、密钥走 `${VAR:-}` 注入、api 用 expose 不用 ports、健康检查依赖链、utf8mb4 |

> **静态验证过程中我自己踩了一个坑，值得记下来** ——
> 第一版校验脚本直接在原文上跑正则，结果**注释里出现的**
> "没有 `location /`" 和 "apt-get install ffmpeg" 被当成了真实配置，报了 2 个假 FAIL。
> 教训：**工具本身也会错，报 FAIL 时先怀疑工具**。

### A3. 本轮修掉的五个真实缺口（都是新功能带来的）

| 缺口 | 后果 | 修复 |
|---|---|---|
| compose 里**没有 media 卷** | 容器重建后**用户生成的图和视频全丢** | 加 `./media:/srv/app/backend/media` 绑定挂载 |
| compose 里**缺 IMAGE_/TTS_/VIDEO_ 环境变量** | 部署后跑的还是 mock，不是真模型 | 补齐 50 个环境变量，走 `${VAR:-默认}` 从 `.env` 注入 |
| nginx **没有 `location /`** | 接口能调、文档能开，但 **Web 界面打不开**（"一半能用"，最难查） | 加兜底 `location /` + `/assets/` 长缓存 + 媒体流不缓冲 |
| 构建上下文是 `backend/` | **前端产物进不了镜像**，界面永远 404 | 上下文改为仓库根 + 多阶段构建（node 构建 → 只把 dist 拷进最终镜像） |
| **没有 `.dockerignore`** | **`backend/.env`（真实 API Key）会被打进镜像**；`.venv` 拖慢构建 | 新建仓库根 `.dockerignore`（`.gitignore` 对 Docker **无效**） |

## B. 装好 Docker Desktop 后，按顺序执行

预计 10~15 分钟（第一次构建要装 pip / npm 依赖）。

### 第 0 步：确认 Docker 可用

```bash
docker --version          # 需要能输出版本号
docker compose version    # 需要 v2（命令是 docker compose，不是 docker-compose）
docker info               # 能连上守护进程才算真的可用（Docker Desktop 要启动着）
```

### 第 1 步：准备密钥文件

compose 会自动读取 **`backend/.env`** 做变量替换（你平时开发用的那个文件直接就生效）。

```bash
cd backend
ls -la .env        # 确认存在且里面有真实 Key
```

如果还没有，从模板复制：`cp .env.example .env`，至少填上：
`JWT_SECRET_KEY`、`LLM_API_KEY`、`IMAGE_API_KEY`、`TTS_API_KEY`。

> ⚠️ **上线前必须换掉 `JWT_SECRET_KEY`**：
> `python -c "import secrets; print(secrets.token_hex(32))"`

### 第 2 步：构建并启动

```bash
cd backend
docker compose up --build
```

**预期输出顺序**（健康的启动流程）：

```
db-1     | ... ready for connections          ← MySQL 先就绪
api-1    | [entrypoint] 执行数据库迁移（幂等）...
api-1    | INFO  [alembic.runtime.migration] Running upgrade  -> 6e3ce928223b, ...
api-1    | ...（共 9 条，最后一条是 shots clip_path / clip_error）
api-1    | INFO:     Application startup complete.
nginx-1  | ... start worker processes
```

**验收标准**：api 日志里能看到 **9 条** `Running upgrade`，最后三个容器都起来。

### 第 3 步：验证容器健康

```bash
docker compose ps
```

**验收标准**：`db` 和 `api` 的 STATUS 都是 `Up ... (healthy)`。

### 第 4 步：验证接口（注意是 nginx 的 8080，不是 8000）

```bash
curl -i http://localhost:8080/api/v1/health     # 期望 HTTP 200 + {"status":"ok"}
curl -i http://localhost:8080/docs              # 期望 HTTP 200（离线 Swagger UI）
```

### 第 5 步：验证 Web 界面能打开（本轮修的关键项）

浏览器打开 **<http://localhost:8080>**

**验收标准**：能看到登录/注册界面，**不是 nginx 的 404 页面**。

> 如果 404：说明前端产物没进镜像。
> 排查：`docker compose exec api ls /srv/app/frontend/dist`（应该看到 index.html 和 assets/）

### 第 6 步：验证完整业务链路（真模型）

在界面上或按 README 的 curl 流程：

```
注册 → 登录 → 建短剧 → 加一集 → 生成分镜 → 生成画面 → 生成配音 → 合成视频
```

**验收标准**：
- 分镜表出现 6 个镜头
- 每个镜头能显示画面（**说明"鉴权 + blob URL"这条路在 nginx 后面也通**）
- 成片能在线播放

> 顺便验证 nginx 的媒体流策略：拖动成片进度条**拖不动是已知限制**
> （接口返回 `Accept-Ranges: none`，要支持拖动需要后端加 Range 支持，见 docs/00 待办）。

### 第 7 步：验证媒体持久化（本轮修的关键项）

这是"**生成的图和视频会不会丢**"的验证：

```bash
# 1) 在界面上生成一张图（或一个动态片段）
docker compose exec api ls -la /srv/app/backend/media/shots/ | head

# 2) 停掉并删除容器（保留卷）
docker compose down

# 3) 重新起来
docker compose up -d

# 4) 再看文件还在不在 —— 必须还在！
docker compose exec api ls -la /srv/app/backend/media/shots/ | head
```

**验收标准**：文件仍然存在（宿主机的 `backend/media/` 里也能直接看到）。

### 第 8 步：验证 MySQL 里真的建了表

```bash
docker compose exec db mysql -udrama -pdrama_password_change_me ai_drama -e "show tables;"
```

**验收标准**：能看到
`users / dramas / characters / episodes / shots / dialogue_lines / generation_logs / generation_tasks / alembic_version`

### 第 9 步：确认新功能的环境变量真的注入了

```bash
docker compose exec api env | grep -E "PROVIDER|MODEL|CLIP"
```

**验收标准**：看到的是**你在 `.env` 里配的真实值**（如 `IMAGE_PROVIDER=openai_compat`），
而不是 compose 里的默认值（`mock`）。如果还是 mock，说明 `.env` 没被读到。

## C. 上线到云服务器前，还要做的五件事

1. **换掉所有默认密钥**：`JWT_SECRET_KEY`、`MYSQL_PASSWORD`、`MYSQL_ROOT_PASSWORD`
2. **加 HTTPS**：nginx 加 `server 443 ssl` 块，用 Let's Encrypt（certbot）签证书
   （`X-Forwarded-Proto` 已经传了，后端能感知 https）
3. **把 `server_name _` 换成你的域名**
4. **调紧配额**：`DAILY_CLIP_LIMIT` / `DAILY_VIDEO_LIMIT` 是真花钱的，按预算设；
   `LLM_PROVIDER=openai_compat` + 真实 Key
5. **换任务队列**：现在是 FastAPI `BackgroundTasks`（**同进程内存**），
   进程重启会丢任务 —— 生产应换 Celery/RQ + Redis（见 docs/00 待办清单）

## D. 尚未验证 / 已知风险（诚实清单）

| 项 | 状态 | 说明 |
|---|---|---|
| Docker 镜像能否构建成功 | ⚠️ 未验证 | 需要 Docker Desktop。**最可能出问题的是 `npm ci`**（网络/锁文件）和 pip 装包 |
| 容器里前端界面能否打开 | ⚠️ 未验证 | 静态检查已确认路径计算和 nginx 配置正确，但没实机跑过 |
| nginx 配置语法 | ⚠️ 未验证 | 开发机无 nginx，`nginx -t` 无法执行。起 nginx 时若有语法错误，`docker compose logs nginx` 会立刻显示 |
| `--workers 2` | ⚠️ 未验证 | 仅 Linux 支持（Windows 下 uvicorn 不支持多 worker），只能在容器/服务器验证 |
| 容器内 ffmpeg 能否编码 | ✅ 有间接证据 | 视频合成测试就是在 **CI 的 Linux** 上用那份内置二进制跑通的，容器同样是 Linux |
| 登录限流器 | ⚠️ 设计限制 | 进程内内存计数；多实例部署时各算各的，生产应换 Redis |
| 视频 Range 请求 | ⚠️ 已知限制 | 接口返回 `Accept-Ranges: none`，播放器拖不动进度条 |
| `docker-entrypoint.sh` 的换行 | ✅ 已规避 | `.gitattributes` 强制 LF，Dockerfile 里 `chmod +x` 补执行权限 |

## E. 出问题时怎么排查（按症状查）

| 症状 | 最可能的原因 | 怎么查 |
|---|---|---|
| 界面 404，但 `/api/v1/health` 正常 | 前端产物没进镜像 | `docker compose exec api ls /srv/app/frontend/dist` |
| api 一直 restart | 连不上数据库 / 迁移失败 | `docker compose logs api` |
| `Can't connect to MySQL server` | api 比 db 先起来了 | 等 30 秒；确认 `depends_on: condition: service_healthy` 还在 |
| 迁移报 `Table already exists` | 库里已有旧结构（卷继承） | `docker compose down -v` 清库重来（**会删数据**） |
| 界面能开，但生成全都失败 | 环境变量没注入，跑的是 mock 或没 Key | `docker compose exec api env \| grep API_KEY` |
| 生成的图/视频重启后不见了 | media 卷没挂 | 检查 compose 的 `volumes` |
| 合成视频时报 ffmpeg 找不到 | 镜像里 ffmpeg 缺失 | `docker compose exec api python -c "from app.services.ffmpeg import ffmpeg_exe; print(ffmpeg_exe())"` |
| 构建到 `npm ci` 失败 | 锁文件不一致 / 网络 | 本地先跑 `npm ci` 确认；或把 Dockerfile 的 `npm ci` 换成 `npm install` |
| `docker compose` 命令不存在 | 只装了旧版 docker-compose v1 | 升级 Docker Desktop，用 `docker compose`（带空格） |

## F. 一个重要的提醒

**你现在 PyCharm 里跑着的那个 8000 端口服务，改动过代码后需要重启** ——
新增了数据库迁移（`shots.clip_path` / `clip_error`），重启前请先执行：

```bash
cd backend
alembic upgrade head
```

否则接口会报 `no such column: shots.clip_path`
（`create_all` 只建表、**不加列**，这个坑我们踩过两次）。
